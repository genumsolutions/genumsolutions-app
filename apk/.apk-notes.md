## Notes

- `genum-solutions-3.4.6.apk` is a real build output, not a renamed placeholder. Its embedded `assets/app.config` reads `version: 3.4.6` / `android.versionCode: 70`, matching `mobile/app.json`, `mobile/package.json`, and `mobile/src/config/site.ts` (`APP_VERSION = "3.4.6"`).
- This APK is the locally assembled release variant for `arm64-v8a`. It is unsigned-for-distribution as configured by the local `android/app/build.gradle` release signing setup on this machine.
- If you publish a bucket release, do it from the machine/process that can sign the release key and run `node scripts/upload-release.mjs` with valid Supabase secrets; do not assume this local copy is the exact distribution-signed binary unless it was produced by that process.
- `genum-solutions-latest.apk` is now the published 3.4.7 build: byte-identical to `genum-solutions-3.4.7.apk` (same SHA-256), pulled back from the bucket by `node root-apk-sync.mjs`.
- **Signing caveat (live, unresolved):** the published 3.4.7 APK is signed with the local debug key (SHA-1 `5e8f1606…`), while the previously published 3.4.4 was signed with a different key (`2fb086e5…`, a debug keystore from the `C:\bs` build machine). Debug keystores are per-machine, and this repo has no `android/keystore.properties`, so every release built on a different machine changes the signing identity. A device with the old release installed cannot install 3.4.7 over it (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`); fresh installs are unaffected. Fixing this needs a real release keystore, kept outside the repo, used by every build from now on.
- `genum-solutions-3.4.4.apk` here is an older mirror; it is not updated automatically by this local build.

- `mobile/android/app/build.gradle` — gitignored; edited on disk by `scripts/bump-version.mjs` for local native builds.
